# 个人事项标签体系与复制/检索/筛选优化（2026-08-15）

## 需求背景

个人中心「事项」模块（`User/Task`，非独立路由，挂在 `/user-profile?tab=task`）一次性做了多轮优化：

1. **状态与提醒联动**：事项状态为「已完成」（`done`）时，事项提醒自动改为「不提醒」且不可选。
2. **基于原有事项快速复制**：从一条已有事项微调快速新建，避免重复填写；同时发现并修复了复制时把旧 `id` 传给 `add` 接口导致的 ID 重复报错。
3. **表格视图补复制操作** + **关键字检索** + **筛选区重构**：默认只留关键字+状态，其余筛选项收进「更多筛选」下拉（参考「我的创作」`UserArticle` 的 `el-popover` 模式），批量删除上移到第一行。
4. **发挥标签字段价值**（用户拍板三选）：标签云+标签筛选、点击标签筛选、标签配色。
5. **标签必填 + 已有标签下拉可选**：新建/编辑时标签设为必填，已有标签直接从下拉选择（复用标签统计接口），不必每次手输。

## 关键发现与分析

- **复制链路**：通过 `emitter` 新增 `task:copy` 事件，`index.vue` 以 `optType='copy'` 打开弹窗；弹窗 `confirmHandler` 将 `copy` 与 `add` 同走 `addUserTaskApi`。**坑**：表单回填 `props.row` 时用解构 `...rest` 只剥离了 `score/createTime/updateTime`，漏了 `id`，导致旧 `id` 混进 `add` 请求报「ID 重复」。修复为同时解构剥离 `id`。
- **关键字检索**：后端 `get_user_task_list` 新增 `keyword` 参数，`Q(title__icontains=...) | Q(description__icontains=...)`（用户选定「标题+描述」）。
- **标签存储与筛选**：`tags` 在模型里是**逗号分隔字符串**（`add/update` 用 `','.join`，序列化 `split(',')` 成数组）。用 `icontains` 精确匹配会误命中（`work`→`homework`），故 `tag` 精确筛选改为**内存过滤 + 手动分页**（个人数据量小，够用；数据量大需改 `JSONField` 或关系表）。
- **序列化 bug 修复**：空标签 `''.split(',')` 得到 `['']`（而非 `[]`），会导致渲染出空标签，修正为过滤空串。
- **标签配色**：`getTagColor(tag)` 按名字哈希映射到 10 色固定调色板，保证同一标签始终同色；放在 `src/utils/tool/index.ts`（该目录被 `unplugin-auto-import` 扫描 + `vueTemplate:true`，模板内免 import）。
- **标签云/点击筛选**：新增 `UserTaskTagCloud.vue`（标签+数量、激活高亮、清除筛选）；卡片加 `tagClickable` 属性控制标签是否可点击（列表/表格开，面板纯展示）。
- **事件类型补全**：`src/utils/eventBus/index.ts` 的 `Events` 映射此前遗漏 `task:copy`，本次补上。
- **标签必填校验**：`formRules` 加 `tags` 规则需 `type: 'array' as const`（否则 `string` 与 async-validator 的 `RuleType` 不兼容，且不指定 `type` 时空数组不会触发 required）。

## 后续注意事项

- **后端需重启 Django 服务**：`keyword`/`tag` 筛选与标签统计接口改动才生效（无数据库迁移，纯视图逻辑）。
- **标签精确筛选是内存过滤**：当前按逗号分隔存储 + Python 侧过滤，个人数据量适用；若事项量大幅增长，建议将 `tags` 改为 `JSONField`（存数组，`tags__contains=[tag]`）或抽关系表，需一次最小迁移 + 数据迁移。
- **面板视图标签纯展示**：面板按状态分组、无筛选语境，标签仅彩色展示不可点击；如需「面板点标签跳转列表筛选」，需在 `index.vue` 增加 `pageStatus` 切换 + 跨组件传参（已备注未实现）。
- **标签必填的副作用**：编辑**无标签的存量任务**时会提示补标签；若存量有大量空标签任务，可能造成编辑摩擦。
- **`getTagColor` 依赖 `auto-imports.d.ts` 重新生成**：dev server 热更新会自动刷新，冷启动或首次类型检查可能短暂报「找不到 `getTagColor`」。
- 复制时所有可编辑字段（含状态/时间）原样预填，未做状态重置；如需「复制默认重置为待办」，需另加逻辑。

## 减少 token 使用的建议

1. **抽取公共逻辑**：`TaskList`/`TaskTable` 的筛选区、标签云/标签筛选逻辑高度重复，可抽 `useTaskFilter` hook + 公共标签云组件，后续改动只需读一份。
2. **大文件按需读取**：`UserTaskFormDialog.vue`、`TaskTable.vue` 等较大文件后续修改可用 `Read` 的 `offset/limit` 定位，避免整文件重读。
3. **复用探索结论**：同一文件（如 `task.py`、`service.ts`）在本会话被多次重读，可先确认内存中的文件状态再动手，减少重复 `Read`。
4. **明确范围再动工**：多轮需求（复制→检索→标签）可一次性用 `TodoWrite` 规划后再批量编辑，减少来回确认消耗。
