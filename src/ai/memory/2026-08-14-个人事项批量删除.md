# 个人事项批量删除（2026-08-14）

> 对话开始：2026-08-14　对话结束：2026-08-14 19:15

## 需求背景

个人中心「事项」页面的「列表」和「表格」两个视图需要批量删除能力，且**翻页勾选不丢失之前已选的数据**。原只有单个删除（每行/每卡一个删除按钮）。

## 关键发现与分析

- **后端无需改动**：`delete_user_task`（`modules/user/views/task.py`）已用 `UserTask.objects.filter(id__in=params['ids']).delete()` 支持批量删，前端 `deleteUserTaskApi` 也早已接受 `{ ids: string[] }`。
- **事项页结构**：`User/Task/index.vue` 用 `el-segmented` 三个 tab——`dashboard`(面板/TaskDashboard)、`list`(列表/TaskList)、`table`(表格/TaskTable)。「列表」实为**卡片网格**（复用 `UserTaskCard`），「表格」是 `el-table`。面板无分页，不做批量。
- 列表/表格都基于 `useSearch` 分页（`AppPagination`），`filterUserTaskList` 会把 `pageNumber` 重置为 1。
- **跨页选择两套机制**：
  - 表格：`el-table` 的 `type="selection"` 列 + `reserve-selection` + `row-key="id"`，内部按 rowKey 匹配；`taskList` 是 computed 每次重建新对象也不影响（按 `id` 匹配）。`@selection-change` 回调拿到的是「保留 + 当前页」全集，直接映射为 id 集合。
  - 列表：卡片无表格选择列，用 `Set<string>` 手动维护选中 id，翻页天然不丢。
- 抽公共 hook `useTaskBatchSelect` 复用「id 集合 + 批量删除 + 确认弹窗」逻辑，减少两视图重复。

## 后续注意事项

- **无后端改动，无需迁移/重启**。
- `reserve-selection` 依赖 `row-key="id"` 才生效；清空保留选择用 `tableRef.value?.clearSelection()`（会同步触发 `selection-change` 清空 id 集合）。
- 类型检查 `vue-tsc --noEmit` 存在**既有历史报错**（`SysSettings`、`ArticleTag`、`Activity`、`HotArticle`、`Home`，以及 `TaskTable.vue` 里 `getDictLabelByKey(statusList, ...)` 两处 `inject` 返回 `| undefined`），与本次改动无关；本次新增/修改代码无类型错误。
- `UserTaskCard` 的 `selectable` 默认 `false`，`TaskDashboard`（面板）及 `WorkBench/Home` 的复用处不显示勾选框。
