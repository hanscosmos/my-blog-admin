# 用户动态组件重构（2026-08-14）

## 需求背景

个人中心「动态」页原本只显示一行文字 `于X前 <action>`，且 `action` 里塞了标题（如 `发表文章-标题`），信息量少、样式简陋。用户要求：

1. 改为「发表了文章/草稿」作为动作头，下方展示文章/草稿的具体信息（封面、标题、摘要、分类、时间），可点击跳转查看；文章/草稿可能已被删除，需兼容（硬删除后优雅降级为「已删除」占位）。
2. 新增动态类型（用户最终确认）：**更新文章、删除文章、事项操作（创建事项/完成任务）**，未选「置顶文章」。

## 关键发现与分析

- `UserActivityLog` 模型已有 `targetType`（干净的 `publish_article`/`create_draft`）和 `extraData`(JSON) 字段，天然适合承载结构化信息；`action` 字段原来是 hack，把标题拼进字符串里。
- **文章是硬删除**：`delete_article` 用 `Article.objects.filter(id=...).delete()` 直接删行，删除后 `targetId` 查不到记录，因此「删除文章」类动态的标题必须提前存入 `extraData` 才能展示。
- `targetType` 本就干净，前端按 `targetType` 映射动作文案即可，**旧历史数据无需迁移**就能正常显示；只有「已删除的旧文章」因历史 `extraData` 为空而占位不带标题。
- 动态列表接口 `get_self_activity_log` 原本只 `.values(...)` 返回 5 个字段，改为分页后逐条解析、按 `targetId` 关联 `Article` 表补充 `article` 详情（含分类名，`ArticleCategory` 解析）。
- 任务状态 `'done'` 表示完成；`edit_user_task` 需在 update 前取旧 `status`，判断「旧 != done 且新 == done」才记录 `complete_task`，避免重复/误记。
- `edit_article` 中草稿转发布会把 `createTime` 重置为 `datetime.now()`（已有逻辑）。
- 序列化统一走 `utils/tools.py` 的 `json_handle` → `ComplexEncoder`，可自动处理 UUID/datetime，无需手动 str。

## 改动清单

### 后端（my-blog-service）
| 文件 | 改动 |
|------|------|
| `modules/article/views/article.py` | `add_article`：改用干净 `action` + `extraData={'title': ...}` 分别写 `publish_article`/`create_draft`；`edit_article`：草稿→发布记 `publish_article`，已发布→已发布新增 `update_article`；`delete_article`：删除前取标题写 `delete_article`，再硬删除 |
| `modules/user/views/task.py` | 引入 `add_user_activity`；`add_user_task` 记 `create_task`；`edit_user_task` 记 `complete_task`（完成时才记） |
| `modules/user/views/user.py` | `get_self_activity_log` 改为分页后逐条返回 `{ id, targetId, targetType, action, createTime, extraData, article }`；新增 `_resolve_activity_article`（文章类按 targetId 关联，已删除返回 null）；移除不再使用的 `res_limit` 导入 |

### 前端（my-blog-admin）
| 文件 | 改动 |
|------|------|
| `src/types/user/index.ts` | 重定义 `IActivityItem`，新增 `IActivityArticle`、`extraData`、`article` 字段 |
| `src/views/pages/User/Activity/index.vue` | 重写渲染层：`targetType → { label, icon, color }` 映射动作头；文章类渲染封面/标题/摘要/分类卡片（`article` 为空降级「已删除」占位）；事项类单行「动作《标题》」；点击跳转（正文→`ArticleDetail`、草稿→`UpdateArticle`）；保留 `useSearch` 无限滚动与 `updateTabCount` 上报 |

## 后续注意事项

- **后端需重启**：Django 代码改动后需重载/重启服务才生效。
- **接口返回结构变化**：`/user/activity/list` 新增 `extraData`、`article` 字段，前后端需同步（本次已同步）。
- **历史已删除的旧文章**：因历史 `extraData` 为空，占位文案不带标题，属可接受边界。
- **未做/可选**：置顶文章类型（用户未选）；删除草稿未区分「文章/草稿」文案；事项类动态暂为纯文本，未做点击跳转；若需补充可继续。
