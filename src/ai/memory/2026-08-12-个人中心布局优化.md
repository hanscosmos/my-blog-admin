# 个人中心布局优化（2026-08-12）

## 需求背景

个人中心页面在笔记本屏幕上内容展示区高度不足，"我的创作"和"个人事项"可见条目太少。参照知乎个人中心的设计，将上下布局改为左右两栏布局，同时解决统计数据延迟加载和 `userId` 丢失的问题。

## 关键发现与分析

### 1. 垂直空间不足的根因

原布局为上下结构：顶部 header 卡片 200px + tab 栏 48px，在 1366×768 屏幕上实际内容区仅约 360px。

### 2. 统计数据延迟显示

文章/动态/事项数量由子组件通过 `inject` 上报，只有切换到对应 tab 才会触发子组件挂载并上报。改为后端提供统一的统计接口 `/user/stats`，页面加载时一次性获取。

### 3. userId 丢失导致编辑/删除按钮消失

`ArticleListItem` 和 `ArticleCard` 通过 `isAuthor`（比较 `store.userInfo.id` 与 `article.authorId`）控制按钮显隐。后端 `/user/get/self` 接口不返回 `id` 字段，store 中的 `id` 仅来自登录。若 localStorage 被清空或 store 重置，刷新 Profile 页面后 `id` 为空 → `isAuthor` 为 false → 按钮消失。

**修复**：后端返回 `id`，前端同步写入 store。

### 4. 后台技术栈

Django 5.0.6 + DRF 3.15.2，函数式视图（非 DRF ViewSet），JWT 认证中间件，MySQL 数据库。

## 改动清单

### 后台（my-blog-service）

| 文件 | 改动 |
|------|------|
| `modules/user/views/user.py` | `get_self_info` 返回增加 `'id': str(user.id)` |
| `modules/user/views/user.py` | 新增 `get_user_stats` 视图，查询文章/动态/事项 count |
| `modules/user/urls.py` | 注册路由 `path('stats', get_user_stats, ...)` |

### 前端（my-blog-admin）

| 文件 | 改动 |
|------|------|
| `src/api/user/type.ts` | `UserInfoType` 增加 `id?: string`；新增 `UserStatsType` |
| `src/api/user/index.ts` | 新增 `getUserStatsApi` 接口函数 |
| `src/views/pages/User/Profile/index.vue` | **核心重构**：上下布局 → 左右两栏；左侧个人信息卡（统计+快捷跳转）；右侧全高 tab 内容区；`onMounted` 调用统计 API；tab 标签显示数量；同步 `id` 到 store |
| `src/views/pages/User/Article/index.vue` | 移除"我的创作（N）"标题行；布局切换按钮精简；通过 inject 上报文章数 |

### 布局变化

```
之前：上下结构                      之后：左右两栏
┌──────────────────────┐           ┌────────┬───────────────────┐
│ 头部卡片（200px）     │           │ 个人卡片 │ Tab: 动态(45) ...  │
├──────────────────────┤           │ (256px) │                   │
│ Tab 栏               │           │ 头像    │ 内容列表           │
├──────────────────────┤           │ 统计    │ （全高，~600px+）  │
│ 内容区（~360px）     │           │ [编辑]  │                   │
└──────────────────────┘           └────────┴───────────────────┘
```

## 后续注意事项

1. **后台需要重启**：新增的 `/user/stats` 接口和 `get_self_info` 返回字段需要重启 Django 服务生效。
2. **统计刷新时机**：当前仅页面加载时获取一次，子组件 inject 机制保留用于数据变更后的实时更新（如删除文章后数量同步）。
3. **事项计数**：`tabCounts.task` 未被子组件上报，目前仅依赖 API 初始值。
4. **左侧卡片高度**：移除了 `self-start`，左右等高。若右侧内容区为空时左侧卡片会有空白区，当前设计可接受。
