# AI 聊天助手引入（2026-08-12）

## 需求背景

用户希望在博客管理后台引入 AI 能力，分四个目标：
1. 全局唤醒 AI 助手进行聊天
2. 助手对项目有跟踪了解，能提建议
3. 分析用户行为模式
4. 特定场景发挥作用（文章摘要、点评、修改意见）

决定渐进式引入，**阶段一只做核心聊天助手**：右下角悬浮按钮 + 聊天面板 + SSE 流式对话。

## 技术选型

- **LLM Provider**：OpenAI 兼容 API（用户实际使用 DeepSeek `deepseek-v4-pro`）—— 见后续注意事项
- **后端代理**：Django 5.0 + DRF，Python 后端 `my-blog-service`（与本项目同级目录）
- **流式方案**：前端原生 `fetch` + `ReadableStream` 解析 SSE
- **持久化**：Pinia + persistedstate（localStorage key: `aiChat`）
- **Markdown 渲染**：复用已全局注册的 `<v-md-preview>` 组件
- **主题**：CSS 自定义属性（`--sys-bg-color`、`--sys-text-color`、`--sys-border-color`、`--theme-color`）

## 已知问题

### 1. Pinia store 初始化顺序错误（待修复）

AiChatWidget 组件挂载时触发 `getActivePinia() was called but there was no active Pinia`。

**原因**：`src/ai/services/aiApi.ts` 在模块顶层调用了 `useUserInfoStore()`，该函数在 Pinia 实例创建前被执行。

**修复方向**：
- 将 `useUserInfoStore()` 调用从模块顶层移到函数内部（lazy access）
- 确保 `sendChatMessage` 内的 store 访问延迟到运行时

### 2. 模型需切换为 DeepSeek

用户无 OpenAI 充值额度，需使用 DeepSeek 的 `deepseek-v4-pro` 模型。

**需修改**：
- 前端 `src/ai/constants.ts`：`DEFAULT_MODEL` 改为 `'deepseek-v4-pro'`
- 后端 `.env`：`AI_API_KEY` 替换为 DeepSeek API Key，`AI_API_BASE_URL` 改为 `https://api.deepseek.com/v1`，`AI_MODEL` 改为 `deepseek-v4-pro`

### 3. App.vue 中 AiChatWidget 已注释

当前 `src/App.vue` 中 `<AiChatWidget />` 被注释掉，避免 Pinia 报错阻塞页面加载。修复问题 1 后可恢复。

## 后续注意事项

- 后端 `.env` 中的 `AI_API_KEY` 目前是 OpenAI 的 key（`sk-proj-...`），用户在切换到 DeepSeek 时需替换为 DeepSeek 的 API Key
- `modules/ai/` 不使用数据库模型，无需 `makemigrations` / `migrate`
- 系统提示词（`DEFAULT_SYSTEM_PROMPT`）在 `src/ai/constants.ts` 中，后续阶段可扩展注入更多项目上下文
- SSE 流式请求不走 Axios 拦截器，token 由 `aiApi.ts` 手动从 `useUserInfoStore` 获取并注入请求头
