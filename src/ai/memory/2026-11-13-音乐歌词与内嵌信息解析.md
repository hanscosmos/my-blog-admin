# 音乐歌词与内嵌信息解析（2026-11-13）

- **对话时间**：2026-11-13 18:52 ~ 2026-11-13 20:42（本地时间）
- **涉及项目**：my-blog-admin（前端）、my-blog-service（后端）

## 需求背景

1. 音乐播放器支持可选歌词：管理端可上传 LRC / 纯文本歌词，播放时随进度高亮展示。
2. 上传音频时自动读取文件内嵌的封面、歌名、歌手、歌词，减少手动找图。
3. 历史歌曲需要补全：增加「解析」按钮，按已上传的音频 URL 重新解析并补全缺失信息。
4. 样式调整：歌词上传按钮换行 → 加宽弹窗；播放器切换歌词/播放列表时宽度跳动 → 固定宽度。

## 关键发现与分析

- **歌词存储选型**：LRC 文本直接存 `sys_music.lyric`（`TextField`），随 `/resource/music/all` 返回，播放器无需额外请求；不采用「上传 .lrc 到 COS 存 URL」方案，避免额外请求与失败处理。
- **歌词上传**：前端 `el-upload :auto-upload="false"` 本地读取，不经过上传接口；UTF-8 严格解码失败后回退 `gbk`（中文 LRC 常见编码）。歌词长度 20000 字符、文件 200KB，前后端保持一致。
- **内嵌信息解析（上传时）**：使用 `music-metadata` 的浏览器 API `parseBlob` / `selectCover`，支持 MP3/FLAC/MP4/OGG/WAV；歌词带时间轴时还原为 LRC 文本；解析出的封面复用 `uploadFile(type='music-cover')` 上传。
- **通用组件坑**：`AppImageAutoUpload` 原先只在 `onMounted` 读取一次 `defaultUrl`，父组件异步回填封面后预览不刷新（表单值实际已写入）。已增加 `watch` 支持异步回填。
- **历史歌曲解析走后端**：实测 CDN 音频的 HEAD / GET 响应均无 `Access-Control-Allow-Origin`，浏览器无法直接 `fetch` 旧链接解析 → 改为后端下载 + `mutagen` 解析，避开 CORS。
- **后端解析策略**：支持 ID3（MP3/WAVE/AIFF）、FLAC、MP4/M4A、OGG Vorbis/Opus；只补充数据库空字段，不覆盖已有歌词/封面/歌名/歌手；封面服务端以 `music-cover` 类型上传并沿用长缓存；音频下载上限 80MB。
- **播放器宽度**：统一固定 400px（≤640px 屏幕 340px），移除歌词态 440px 的宽度切换与过渡。

## 后续注意事项

- **数据库迁移**：需执行 `python manage.py migrate resource` 后歌词字段才生效。
- **迁移文件不入库**：`migrations/` 被 `.gitignore` 忽略，换环境需重新生成/携带 `0004_music_lyric.py`。
- **依赖安装**：前端 `npm install`（`music-metadata`）；后端 `pip install -r requirements.txt`（`mutagen==1.47.0`）。
- **CORS 现状**：CDN 未配置 CORS，前端不能直接解析历史音频链接；当前历史解析全部走 `/resource/music/extract`。
- **只补空字段**：解析不会覆盖已有歌词/封面/歌名/歌手；无内嵌标签时返回「未发现可补充的内嵌信息」。
- **限制**：歌词 ≤20000 字符；内嵌封面 >10MB 跳过；解析下载音频 >80MB 拒绝。
- **AppImageAutoUpload 行为变化**：父组件把 `defaultUrl` 设为空会清空预览，异步回填场景需注意。
- **未实现**：批量解析、歌词时间轴手动微调、在线歌词搜索。
