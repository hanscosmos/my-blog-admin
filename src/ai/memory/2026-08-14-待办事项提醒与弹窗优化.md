# 待办事项提醒与弹窗优化（2026-08-14）

## 需求背景

个人中心「事项」组件包含待办（`todo`）/进行中（`pending`）/已完成（`done`）/已取消（`aborted`）三类状态（字典 `USER_TASK_STATUS`）。本次涉及三件事：

1. **待办事项提醒**：为待办/进行中任务加提醒能力。用户拍板：复用 `deadline` + 提前量、通道用「应用内弹窗 + 顶部角标」（不做浏览器桌面通知）、后端新增精简提醒列表接口。
2. **动态记录守卫**：原逻辑「创建任务无条件记一条动态」不合理（补录已完成的事也凭空多一条），改为仅创建 `todo`/`pending` 记动态；「标记完成」保留记动态。
3. **新建弹窗优化**：字段多（14 个）、必填 4 项，优化为「只填标题+截止时间」，其余走默认值。

## 关键发现与分析

- 任务模型 `UserTask`（Django，`modules/user`）已有 `deadline`/`startTime`/`endTime`，序列化器 `exclude=[]` 全字段输出；`add/update` 直接 `create(**params)`/`update(**params)`，**前端只要把新字段传进来就自动落库，无需改 add/update 逻辑**。
- 提醒字段设计为 `remindBeforeMinutes`（整型分钟，`-1`=不提醒），触发时间 = `deadline - remindBeforeMinutes` 分钟；下拉取值 `-1/0/5/15/30/60/1440`。
- 顶部 [TodoListBtn](../../layout/components/TopBar/components/TodoListBtn/index.vue) 原是占位组件，是放角标 + 下拉面板的天然位置；`useRouter`/`useRoute` 已全局自动导入（`vue-router/auto`）。
- 任务页**不是独立路由**，而是 `/user-profile` 页内的 tab（`key='task'`），跳转需走 `/user-profile?tab=task`，Profile 的 `onMounted` 读 `route.query.tab` 切 tab。
- 动态：`UserActivityLog` 已有 `targetType`/`action`/`extraData`；`create_task`/`complete_task` 两种类型**前后端都已存在**（前端 `activityMetaMap` 已配图标/文案），无需新增类型。`edit_user_task` 的 `complete_task` 用 `was_done` 判断「旧 != done 且新 == done」，天然满足「直接建为 done 不再误记」。
- **评分默认值 bug**：前端 `originalForm` 评分默认 `0`，后端模型默认 `3`，不碰评分直接建任务得分被算成 0。
- 踩坑：CSS 变量名是 `--sys-text-secondary-color`（非 `--sys-text-color-secondary`）；`el-popover` 内容 teleport 到 body，**scoped 样式无法命中**，需用 `popper-class` + 非 scoped 样式（或 `:deep`）。

## 后续注意事项

- **后端需迁移 + 重启**：执行 `.venv/bin/python manage.py migrate user` 落 `remind_before_minutes` 列；Django 代码（提醒接口 + 动态守卫）改动后需重启服务才生效。
- **提醒是纯前端**：仅页面打开时生效，`UPCOMING_WINDOW`（24h）控制角标/下拉「临近到期」窗口，在 `useTaskReminder.ts` 顶部可调。
- **动态守卫的语义边界**：直接建 `done`/`aborted` 不记动态；`todo/pending` → `done` 记「完成任务」；默认新建即 `todo` 会记「创建事项」。
- **默认 `status='todo'` 的副作用**：想直接记「已完成」需手动把状态下拉改成已完成，否则按待办记动态。
- 弹窗「评分折叠」内容在 `el-collapse-item` 内仍参与 `el-form` 校验（评分无 rules，无影响）；编辑已有任务时折叠区保持收起，自定义评分需手动展开查看。
