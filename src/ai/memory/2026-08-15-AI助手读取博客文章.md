# AI 助手读取博客文章（2026-08-15）

> 对话开始：2026-08-15　对话结束：2026-08-15

## 需求背景

AI 助手无法读取用户的博客文章。用户让它「根据文章提建议 / 写摘要」时，模型表示无法阅读，让用户提供链接；用户提供本地 `localhost` 链接后，模型又说无法访问。目标是让 AI 助手能访问到博客与文章内容。

## 关键发现与分析

- **架构根因**：AI 助手本质是「纯转发代理」——前端把 `系统提示词 + 消息` 发给后端 `modules/ai/views/chat.py`，后端原样转发给 OpenAI 兼容 API（DeepSeek）。模型**没有工具、没有联网、没有数据库访问能力**，且运行在云端，`localhost` 对其天然不可达，所以既读不到文章、也打不开链接。
- **方案选型**：对比了三种方案，最终选 **Function Calling（工具调用）**（另两种：RAG 向量检索太重、前端注入当前文章覆盖面太窄）。理由：后端本就是 Django，文章数据（`modules/article/models.py` 的 `Article` / `ArticleDetail`）在库里，加工具最自然。
- **后端工具**：给模型定义两个工具——`search_articles`（按标题/摘要关键词搜文章）、`get_article_content`（按 id 读正文 Markdown），后端用 ORM 查库，非流式工具调用循环（最多 5 轮，累计 token）。
- **正文来源分三种页面**：详情页走**查库**（工具）；发布/编辑页正文在**前端编辑器文本框**（新文章 DB 无记录、编辑页可能含未保存修改，查库会拿到旧版），需**前端注入**。
- **关键 bug（本轮最耗时）**：`useRoute()` 原写在 `buildSystemPrompt()` **内部**，而该函数在 `send()`（点击发送的事件回调）里才执行——此时已不在 Vue `setup()` 上下文，`useRoute()` 底层的 `inject()` 返回 `undefined`，导致 `if (route)` 恒为假，**「实时上下文 + 当前文章 id」从未注入过**。这解释了模型一直说「无法读取 URL/query 参数」「无法感知是哪篇文章」。修复：把 `useRoute()` 提到 `useAiChat()` 顶层（setup 阶段调用一次），复用响应式 `route` 对象。

## 后续注意事项

- **工具调用依赖上游模型支持 `tools`**（OpenAI Function Calling 格式）。用户模型为 `deepseek-v4-pro`，实测工具能力可用（模型回复自述「我可以用文章 id 读内容」）。
- **权限范围**：工具只查当前登录用户（`author = user_id`）且未删除的文章。
- **体验变化**：工具循环为非流式，答案**一次性返回**（非逐字流式），等待期间前端显示打字动画。如需恢复逐字流式，可再做「工具循环跑完后最后一轮流式返回」的优化。
- **编辑页正文注入上限 8000 字符**，超长自动截断并标注。
- **若上游模型不支持 `tools`**，可退化为「后端按关键词/id 预取正文注入上下文」的兜底方案（无需工具调用）。
- **无后端迁移**：AI 模块复用已有 article 表，无需 `makemigrations` / `migrate`。

## 减少 Token 使用的建议

1. 大文件（如 `AiChatPanel.vue` 850+ 行）**按需分段读**，不要整文件读。
2. 排查阶段先用 `grep` / 搜索定位到精确位置，再针对性地 Read，避免整目录扫描。
3. 已在上下文中的文件**不要重复 Read**（编辑前已读过即可，Edit 失败会报错提示）。
4. 代码改动直接用 `Edit` 精确替换，而非 Read 全文后再改。
