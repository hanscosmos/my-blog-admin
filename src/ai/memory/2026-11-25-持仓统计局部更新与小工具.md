# 持仓统计局部更新与小工具（2026-11-25）

- 对话时间：2026-11-25 12:38 – 12:50（UTC+8）
- 涉及项目：`my-blog-admin` + `my-blog-service`

## 需求背景

- 把「市场行情」里的小工具（金价换算、计算器）也放进「我的持仓」。
- 汇总区「统计分析」按钮下方新增「一键更新」，把当前各类别金额同步到统计快照。
- 每个品种（大类：基金类别 / 现金两类；小类：单支基金 / 单项现金）在「趋势」按钮前新增「更新」，只更新对应品种的统计快照。

## 关键发现与分析

- 原快照是「按天整份覆盖」：`HoldingSnapshot(user, snapshotDate)` 唯一，`record_holding_snapshot` 每次用当前全部持仓重写当天记录，无法直接做单品种更新。
- 与用户确认后的口径：**沿用同一个记录接口，增加 `keys` 数组参数**。不传/空数组 = 一键更新全部（不含已清仓）；传 key 列表 = 只合并对应品种。
- key 约定：
  - 大类：基金类别 `bond/equity/mixed/...`；现金 `cash_money_fund` / `cash_deposit`。
  - 小类：`fund:<基金代码>`、`cash:<现金记录id>`。
  - 后端用「命中明细 `key` 或所属 `group`」匹配，因此大小类共用一套参数。
- 局部合并策略：
  - 有当天快照：以当天快照为底，移除命中 key 的旧明细，追加当前命中明细；无当天快照：以当前全量明细为底（避免只落一个品种导致汇总缺失）。
  - 汇总金额用「基准值 + 新增明细 − 移除明细」增量维护，保留原有的基金/现金汇总口径（含已清仓成本等）。
  - 局部更新时保留快照原有 `complete` 标记，避免其他品种的行情缺失状态被覆盖。
- 小工具无需复制代码：直接复用 `MarketBtn/components/MarketToolsPanel.vue`，在持仓弹窗标题栏加图标、抽屉展示。
- 行内新增第 4 个链接按钮后原 122px 操作列会拥挤，需加宽到 160px（窄屏断点 150px），并清零组头部相邻按钮的默认外边距。

## 后续注意事项

- 当天没有快照时，任意局部更新会以「当前全量」为底落一份快照，效果等同整份记录；这是为了保证总额完整。
- 局部更新保留旧的 `complete`，若只想刷新完整性状态，需走「一键更新」。
- 已清仓基金仍不进入快照；对某个大类更新时，当天快照中该类的历史已清仓明细也会被移除。
- 操作列宽度 160px 是按键数量估算的，若后续再加按钮或文案变长需重新评估；移动端仍回落为两列布局。
- 后端若未开启自动重载，需要重启服务后再试接口。
- 验证结果：后端 `py_compile` 通过；`vue-tsc --noEmit` 本次文件无新增错误，仍存在 SysSettings / TagDialog / Activity / TaskTable / HotArticle 的既有报错。

## Token 优化建议

- 涉及快照/统计类需求时，先说明「历史数据是否允许局部合并」和 key 口径，可减少一轮确认。
- 指明要复用的组件名（如「行情中心的小工具面板」）比描述功能更省定位成本。
- 给出按钮位置与顺序（如「趋势按钮前」）能一次成型，减少样式返工。
