# 我的资产：金融/实物双页签改造（2026-11-25）

- 对话时间：2026-11-25 12:50 – 13:54（约）
- 涉及项目：`my-blog-admin` + `my-blog-service`

## 需求背景

- 把顶栏「我的持仓」升级为「我的资产」，权限仍仅超级管理员可见。
- 资产分为两块：金融资产（现有基金 + 现金/存款）与实物资产（新增）。
- 用户明确要求：实物资产**完全独立**，不计入金融总资产、资产配置、趋势和快照，两者之间不产生数据牵扯；实物资产表需要图片字段。
- 交互采用顶部统一弹窗 + 「金融资产 / 实物资产」双页签；实物支持增删改查、封面和多张实拍图、按类别分组统计。

## 关键发现与分析

- 金融资产原逻辑集中在 `MarketAssetPanel.vue`（总资产、收益、构成条、分析抽屉、导出、刷新），改造时保持其计算与快照逻辑不变，仅重命名为 `FinancialAssetPanel.vue`。
- 新增轻量容器 `AssetPanel.vue`：`el-tabs` 两个页签，通过 `ref` + `computed` 代理当前子面板的 `updateTime / stale / ready / loading / refresh / exportImage`，保证顶部工具按钮只作用于当前页签。
- 实物资产独立汇总「估值 / 成本 / 累计盈亏 / 收益率」，不参与金融总资产、`sys_holding_snapshot`、周六提醒与趋势；因此后端无需改快照 service。
- 类别方案：预设五类（house/vehicle/precious_metal/collectible/other）+ 自定义类别；自定义类别复用系统字典，`code = PHYSICAL_ASSET_CATEGORY`，字典 `key` 为类别标识、`value` 为显示名称，前端在 `src/config/dict.ts` 注册该分类。
- 图片沿用现有 `/sys/file/upload`（`type=physical`）：`cover` 存封面 URL，`images` 为最多 9 张实拍图 URL 数组；删除资产不清理 COS 文件。
- system 模块的 `migrations/` 被 `.gitignore` 忽略，项目现网表结构实际通过 `my-blog-service/sql/` 维护，因此新表使用 `sql/sys_physical_asset.sql`，不生成迁移。
- Windows 下 `HoldingBtn` 目录被占用，`git mv` 重命名失败；保留原目录名，仅新增 `AssetPanel.vue` 并改入口文案，不影响功能。

## 后续注意事项

- **必须执行建表 SQL**：`my-blog-service/sql/sys_physical_asset.sql`，否则实物接口会报表不存在。
- 自定义类别在「系统管理 → 字典 → 实物资产类别」维护；类别被删除/停用后，历史资产保留原 `category`，展示回退为「其他」。
- 实物页签导出图片会包含图片，若 CDN 未开启 CORS，`modern-screenshot` 导出可能失败；金融页签不受影响。
- 顶部刷新/导出/更新时间只作用于当前页签；实物没有历史趋势和快照，后续如需再做独立实物快照。
- `HoldingBtn` 目录名未修改（Windows 文件占用）；如需统一命名，可关闭占用后执行 `git mv` 并同步更新 `TopBar/index.vue` 的 import。
- 全量 `vue-tsc` 仍有 6 处既有类型错误（`SysSettings`、`ArticleTag`、`User/Activity`、`TaskTable`、`HotArticle`），与本次改动无关；本次新增/修改文件无类型错误。
- 验证已通过：`python manage.py check`、新增后端文件 `py_compile`、`npx vite build`。

## Token 使用建议

- 大型需求先固化「已确认决策清单」，编码阶段直接照清单执行，避免反复回读大文件。
- 改造 700+ 行的既有面板时优先重命名 + 局部 Edit，不做整文件重写。
- 子面板统一用 `defineExpose` 暴露能力，由容器代理，避免复制金融逻辑到新组件。
- 后端复用 `service/fund.py` 的 Decimal/格式化工具，减少重复实现。
- 类型检查先按本次改动路径过滤输出，避免被既有错误淹没。
