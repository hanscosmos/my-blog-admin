# 持仓快照统计与周六提醒（2026-11-23）

- 对话时间：2026-11-23 20:01 – 20:52
- 涉及项目：`my-blog-admin` + `my-blog-service`

## 需求背景

- 持仓面板需要统计图：资产配置圆环图；每周六手动更新持仓，希望有总金额/各品种的历史折线图；周六未更新时提醒。
- 细化要求：支持「总资产 / 资产类别 / 单支基金或单项现金」三级查看收益与总金额；每次手动保存持仓时记录快照；提醒仅在后台页面打开时生效。
- 迭代反馈：图表改为抽屉 + 页签展示；圆环加大、去掉扇区圆角、加渐变阴影；趋势排除已清仓基金；修复「趋势」按钮与左侧数字重叠。

## 关键发现与分析

- 原系统没有任何持仓历史数据，必须新增快照存储；采用「保存/删除时由后端记录」+ `(user, snapshotDate)` 唯一约束 upsert，同一天多次保存只保留最后一条。
- 快照把明细存进 `items` JSON（`key/type/name/code/group/groupName/value/principal/pnl/realizedPnl/status`），一次存储即可支持总资产、类别、单支三级聚合，无需额外明细表。
- 快照的 `totalValue/totalPnl` 等汇总字段与基金/现金组合接口口径一致；明细里的基金 `pnl` 含已实现收益。
- 项目没有后端定时任务，提醒采用「轻量查库接口 + 前端 30 分钟轮询 + localStorage 按日期去重」，只在页面打开时生效。
- Python 坑：`_json_number` 内部调用 `.quantize`，Decimal 字段的空值兜底必须写 `Decimal('0')`，写 `0`（int）会在记录快照时报 `AttributeError`。
- 已清仓基金 `status === 'cleared'`（份额为 0，但保留已实现收益）：记录快照时跳过，读取历史时也过滤旧数据，保证趋势里不再出现。
- Element Plus 相邻 `.el-button` 默认 `margin-left: 12px`，操作列只有 100px 时三个链接按钮会向左溢出，盖住占比/天数文字——这是「趋势按钮与数字重叠」的根因。
- 全局样式 `src/style/UIFramework/index.scss` 把 `.el-tabs__header { margin-bottom: 0 !important }`，因此页签与内容的间距必须通过 `:deep(.el-tabs__content) { padding-top }` 实现（项目已有同类写法）。

## 后续注意事项

- 历史数据从 2026-11-23 开始，越早开始积累越好；空态可点「记录当前持仓」补一个起点。
- 提醒只在后台页面打开时生效，离开页面不会收到任何推送。
- 后端 `.gitignore` 忽略了 `migrations/`，提交 `0009_holding_snapshot.py` 需要 `git add -f`。
- `CashHolding` 没有 Django 迁移（由 `sql/sys_cash_holding.sql` 管理），`makemigrations --check` 会提示，属既有状态。
- 趋势明细聚合不含已清仓基金的已实现收益，但快照 `totalPnl` 汇总字段仍按整体口径统计，二者可能略有差异。
- `npm run build-check` 仍会因既有无关文件的类型错误失败（SysSettings、TagDialog、Activity、TaskTable、HotArticle）。
- 建议人工验证：抽屉页签切换、圆环渐变/阴影、深色模式、隐藏金额、导出图片、窄屏按钮列。

## Token 优化建议

- 一次性写清约束（日期口径、提醒方式、已清仓是否保留），减少多轮修正。
- 样式微调附截图或指出具体元素（如「操作列按钮压到占比数字」），比描述「不好看」定位更快。
- 方案确认后直接说「按方案实现」，跳过重复的 Plan 分析。
- 长会话及时 `/clear` 或分话题新开会话，避免历史上下文反复计费。
