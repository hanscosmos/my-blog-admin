# 音乐播放与统计功能（2026-11-11）

> 对话时间：2026-11-11 12:09 ~ 13:43（UTC+8）

## 需求背景

在博客后台新增音乐播放能力：

1. 播放器样式美观；
2. 记录每首歌的播放次数与累计收听时长，可按统计排序，也可手动拖拽排序；
3. 仅超级管理员可用；
4. 音乐管理（上传等）放在「资源管理」模块下；
5. 音乐信息入库，上传复用已有文件上传链路（COS）。

用户明确不需要「专辑」字段。确认的决策：

- 播放器为后台全局悬浮播放器，仅 `permission.isSuper` 时挂载；
- 管理列表可切换排序方式，播放器歌单始终按手动 `sort` 顺序；
- 8 个 `/resource/music/*` 接口、音频格式 `.mp3/.flac/.wav/.m4a/.aac/.ogg`、50MB 上限、统计在不同超管账号间共享。

## 关键发现与分析

### 数据与权限

- 只记录「每首歌」的累计统计（`playCount`、`listenSeconds`），不建用户维度表。功能仅超管使用，足够且简单。
- **音乐接口不登记 `PERMISSION_PATH_MAP`**，而是在每个 view 里用 `_get_super_user_id` 强制校验超管。若登记成权限码，被授权的普通角色会绕过「仅超管」限制。
- `edit` 只允许写 `name/singer/cover/url/duration`，统计字段无法被前端篡改。

### 数据库迁移

- 数据库已记录 `resource.0001_initial` 与 `system.0001~0005`，但迁移文件在本地缺失（`migrations/` 被 gitignore）。为让 `0002_music` 有依赖，重建了 `resource/0001_initial.py` 基线（Icon/IconCategory/Image/ImageCategory），现有库会跳过，新库可重建。
- 音乐菜单由 `authority/0010_seed_music_menu.py` 按 `code=80003` 幂等种入，`route=MusicManage`，挂在「资源管理」节点下。

### 听歌统计上报

- `<audio timeupdate>` 累加相邻 `currentTime` 增量，**只在 `0 < delta <= 2` 且非拖动进度时计入**，丢弃跳进度的大增量。
- 累计满 15 秒、暂停、切歌、`visibilitychange(hidden)`、`pagehide`、组件卸载时上报 `/music/stat`；页面关闭用 `fetch keepalive`，避免组件卸载后 axios 请求被取消。
- 播放次数在 `play` 事件上报一次 `/music/play`，失败回滚本地计数。
- 后端将单次上报秒数钳制在 `0..300`，防止异常数据。

### 缓存与预加载

- 应用层没有 IndexedDB / Cache Storage / Service Worker，音频仍是浏览器 HTTP 流式播放。
- 后端上传 `music` / `music-cover` 时写入 COS 对象元数据 `Cache-Control: public, max-age=31536000`；文件名含 `nanoid`，不会原地覆盖，可安全长缓存。
- 播放器在列表循环模式下用独立 `new Audio()`（`preload='auto'`）预加载下一首；单曲/随机模式不预载，暂停/切歌/卸载时释放。

### 样式问题

- 播放器卡片原来用 `--theme-card-bg` 作为渐变起点，该变量在浅色模式下仍是深色（如绿色 `#166534`），而文字是深色 `#212529`，导致浅色模式看不清。改为浅色模式用 `--theme-bg → --sys-box-bg-color`，深色模式通过 `html.dark .player-card` 保留原深色渐变。
- 播放列表去掉序号、增加 36px 封面、改为「封面 + 歌名/歌手两行 + 次数 + 时长」布局，最大高度 `220px → 322px`。

## 后续注意事项

- **历史音乐文件没有缓存头**：`Cache-Control` 只对改动后新上传的对象生效，旧文件需重新上传，或在 COS 控制台补元数据。
- 菜单是登录时拉取的，首次上线需重新登录（或刷新菜单）才能看到「音乐管理」入口。
- 统计为全局共享：所有超管账号的播放次数/时长累加在同一份数据上。
- 不支持离线播放；若需要接近 QQ 音乐，可再上 Cache Storage / IndexedDB / Service Worker。
- 新增 authority 迁移编号必须从 `0011` 往后接（`0002~0007` 只在开发机、`0008~0010` 已在库中登记）。
- `npm run build-check` 仍受项目已有的 6 处无关类型错误影响（`SysSettings`、`TagDialog`、`User/Activity`、`TaskTable`、`HotArticle`）。
